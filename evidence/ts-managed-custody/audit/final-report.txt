Review conclusions
1. Early application afterVerify abort now passes the trusted verify response
   through an optional in-process cancellation-context field. The managed scheme
   recovers a missing pendingId only from a valid trusted response. Manual-first
   hook order remains intact; client-authored reservation/cancel fields remain
   rejected. No reservation identity is invented when a response lacks it.
2. Local refund enrichment/signing failure now sends a zero-charge cancel after
   unrecovered failure hooks and retains the original error. Explicit beforeSettle
   directive abort also cancels, while existing thrown-hook and skip-result
   behavior is preserved. Cancel-phase failures do not recursively cancel.
3. The dispatch flag is set before either selected-client or fallback facilitator
   invocation. Actual pending/unknown outcomes retain identity and are not
   automatically canceled. Receipt-bearing/pending local SettleError outcomes are
   excluded too. A recovered failure short-circuits cleanup. Failed cancellation
   retains its identity for an explicit later attempt or reconciliation.
4. All authoritative uint snapshot fields are parsed before the optional replica
   update. Malformed authoritative data still fails the committed receipt closed
   without canceling it. Replica persistence/callback failure instead warns once
   and preserves the exact successful facilitator receipt. The real client's
   response hook then advances its local watermark. Confirmed receipt paths clear
   request context; failed/uncertain calls retain it.
5. Original feature paths remain focused: Go-compatible refund-key salt packing,
   explicit managed capability/refund-consent negotiation, every managed payload
   forwarded despite warm/stale/fresh replicas, exact refund nonce for signatures,
   facilitator corrective proofs for both mismatch reasons, and managed redemption
   worker guard. Shared refund logic preserves default server custody behavior.
6. Core's optional context field/new cancellation reason are a small enabling
   lifecycle change. No new dependencies, TS managed facilitator/storage port,
   legacy source, misleading e2e catalog claim, or unrelated API redesign was added.
   The changeset correctly includes both core and EVM.
